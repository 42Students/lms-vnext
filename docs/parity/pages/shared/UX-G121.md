Status: **DOING — implementation submitted; live browser acceptance not yet verified.**

## Owned routes
- `/tracker` authenticated report intake (reviewed; unchanged)
- `/tracker/issues`, `/tracker/issues/[publicId]`
- `/tracker/audit-findings`, `/tracker/audit-findings/[publicId]`
- Their scoped loading/error states; `/tracker/issues/public` is separately inventoried and remains unchanged.

## User-visible fixes
1. Issue triage runtime-unavailable state now says what the user can do rather than exposing migration IDs and runtime environment flags.
2. The issues list distinguishes **No reported issues yet** from **No issues match these filters** and presents a suitable **Report issue** or **Clear filters** action.
3. A temporarily unavailable issue detail offers an authorized safe destination, to private issues for Super Admin or own reports for a reporter.
4. Issue detail loading now has a meaningful heading, `aria-busy`, and responsive skeleton context.
5. Audit-finding list malformed filters explain non-loading and provide a usable reset; retry link meets touch sizing.
6. Audit detail avoids a redundant request-context fetch and names empty audit event/fix-commit states explicitly, without bypassing service authorization.
