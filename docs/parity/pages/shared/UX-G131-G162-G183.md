### Actual improvements

- **G131:** Make create and edit dialogs real keyboard-submittable forms; require nonempty title and message with native controls; maintain publication consent on both button click and Enter; present explicit title/body lengths and schedule help.
- **G131:** Provide batch selection for the *currently matched, server-offered* placement cells, clear selection, live selection/search context, and a hard 500-college upper bound matching the API's `reviewedCollegeIds` and `collegeIds` schema limits. Do **not** convert selected-college audiences into broadcast-to-all. Keep the final audience recheck, version protections, and publish consent.
- **G162:** Clarify that Super Admin sort and bulk selection are limited to the currently loaded page; show the true selectable count and first-50 dialog limit rather than suggesting hidden rows were shown. Keep 20-item bulk cap and documentary verification safeguards.
- **G162:** Clear stale filter errors on user edits, give TPO a reversible "Clear page filters" control without discarding server filter scope, and show send-back reason length before submission. Review still uses its existing guarded mutation and stale-version handling.
- **G183:** Preserve the reviewer-supplied text of a learner correction request while separating it with normal punctuation from the next action. Populate the **Reviewed by** column from the stored `decidedByName` on the already tenant-scoped export query; keep formula escaping through `verificationCsv`, and do not add any new private data columns.

### Security, roles and cross-surface regression boundaries

- G131 multi-select receives only the currently offered Super Admin authorized college choices; backend independently validates target list, enforces 500-cap, checks audience at publish time and rejects stale changed audiences. No new client-side authority is introduced.
- G162 panel work is presentational and only invokes existing server-enforced review workflows. TPO local filters cannot broaden the authorized server read. A refusal or a missing proof still blocks bulk verification. Private documents and history continue to be gated by existing checks.
- G183 reviewer name is a persisted decision field already present in the authorized verification queue and audit history, not an arbitrary user-supplied email or private document. Query remains scoped by `eq(collegeMemberships.collegeId,scope.collegeId)`, after `requireCollegeVerificationActor` or `requireSuperAdminVerificationCollege`.
- Learner-only negative browser check must confirm no Super Admin authoring or verification queue becomes accessible.
