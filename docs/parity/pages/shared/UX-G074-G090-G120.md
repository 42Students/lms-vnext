## UX-G074 — Mentor task reviews and team coverage

In-scope surfaces: `src/app/(authenticated)/mentor/task-reviews/{page,loading,error}.tsx`, `src/app/(authenticated)/mentor/team-coverage/{page,loading,error}.tsx`.

Issues reviewed and fixes implemented:
- Apply buttons and reset links previously said only `Filter` and `Clear`; now `Apply filters` / `Clear filters` express the action.
- Search and no-match states previously used the generic `No pending task reviews` even with restrictive search/filter input. The task queue now states when **no task reviews match the current filters** versus when the underlying pending queue is empty.
- The team coverage total did not distinguish the currently visible page from all matching projects. A polite status now provides visible page range and filter context; empty-state copy does not imply all current assigned projects are necessarily active.
- Existing authorization, project scope, pagination-query model, submitted-task status, CSV scope and project navigation are unchanged. Error/retry and loading fallbacks were inspected and retained.

Required browser proof: Mentor on desktop/mobile for filtered task queue, filter reset, no-match status, team coverage, invalid-filter recovery and no horizontal overflow. Additional role-negative witness: an authenticated Learner must not see Mentor task review records.

## UX-G090 — Faculty teaching courses and details

In-scope surfaces: `src/app/(authenticated)/teach/courses/{page,loading,error}.tsx` and `src/app/(authenticated)/teach/courses/[deliveryId]/{page,loading,error}.tsx`.

Issues reviewed and fixes implemented:
- Landing-page heading description now explains how teachers find **their courses and class sections** rather than using implementation terms (deliveries and exact sections).
- Key course actions (Students, Attendance, Discussions) were previously **hidden by a closed disclosure** on the detail page. They are now always visible in a compact, wrapping keyboard-focusable navigation area, with the existing safe role-specific destination paths.
- Existing typed course ID validation, revoked-access `notFound`, workspace data, disabled states, course filters, service authorizations and loading/error fallbacks were not modified.

Required browser proof: seeded Faculty course list, a real authorized course-detail link, visible shortcuts on both desktop/mobile, correct target paths and no horizontal overflow.

## UX-G120 — TPO team Everyone and profile verification

In-scope surfaces: `src/app/(authenticated)/tpo/team/everyone/{page,loading,error}.tsx` and `src/app/(authenticated)/tpo/verification/{page,loading,error}.tsx`.

Issues reviewed and fixes implemented:
- Everyone's message route previously silently reset malformed `page` values to page 1. It now explicitly shows an invalid-page recovery link without loading or exposing team messages.
- A failure while reading a later Everyone conversation page previously linked Retry to page 1; retry now **preserves the requested page**. Page navigation now states `Page X of Y` for orientation.
- The verification filter disclosure previously hid applied filters. It now opens when filters are active, displays an active-filter count and supplies a `Clear filters (keep status)` action. The current verification status tab is preserved, and reset returns to page 1.
- Message posting, marking read, notification delivery, profile verification permissions, RLS/tenant policies, export behavior and server read services were not changed.

Required browser proof: seeded TPO on desktop/mobile for invalid page recovery, Everyone page access, verification active-filter display, preserving tab status when clearing and no horizontal overflow.
