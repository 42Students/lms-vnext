# UX-G158 — TPO interactive components review (8 November 2026)

**Canonical status:** `docs/tracker.json#uxReview.groups[UX-G158]`; workstream remains SECURITY. Do not count this UX group as done without exact-SHA passing tests and desktop/mobile browser evidence.

**Scope:** All 15 interaction components in `UX-G158`. This round focused on the announcement delete, send-undo, and receipts workflows, plus keyboard-accessible shortcut discoverability. Other source files in the group were reviewed for server-side mutation ownership, focus/keyboard, busy states and responsive layout; this is not proof they all passed end-to-end testing.

## Changes and expected behavior

- Destructive notice deletion retains the alert dialog and the user’s context on 409/403/503/network failure, shows a legible error, and reenables controls for retry. On verified JSON success it navigates to the same announcements tab and refreshes. All requests remain same-origin and retain the expectedVersion + DELETE server guard.
- Receipt counts now reject malformed API payloads rather than showing contradictory counts or crashing on absent unread rows. If the server reports unread people but no recipient names, the drawer explains that the names are not available instead of saying everyone has read it.
- Undo-send becomes actionable on the first effect rather than waiting for the first one-second interval. A confirmed result is communicated accessibly; a failed mutation remains retryable inside the server’s original 30-second window.
- Existing TPO shortcuts, grid filtering, follow-up composer, notice modal, Everyone controls, and mobile navigation were source-reviewed for preserving current functionality. Do not reinterpret review-only paths as independently certified.
