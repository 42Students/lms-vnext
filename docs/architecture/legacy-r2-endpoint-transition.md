# Legacy R2 endpoint transition — UI caller contract

The **legacy** `/api/v1/upload/*`, `/api/v1/resource-uploads/presign` and public-url utilities are **retired** for vNext callers. Never add a generic proxy, public-bucket fallback, caller-supplied folder or raw-object listing. An old numeric content ID, `materialIndex`, `fileName` or object key is not permission to read a private file. Resolve it to a current tenant-owned resource record first.

This table is a **call-site migration contract**, not a set of compatibility routes. The referenced new endpoints must still check the live membership, parent ownership, audience and role permission. See [file-and-video-apis.md](file-and-video-apis.md) for each payload and response.

| Legacy caller | vNext source of truth | Grant, completion, read and delete |
| --- | --- | --- |
| `POST /api/v1/upload/*` for assignment files | `assignment_submission_files` owned by an enrolled learner and delivery | `POST /api/courses/assignments/{assignmentId}/submission-files`, direct PUT of grant headers/bytes, `POST .../{fileId}/complete`; `POST /api/courses/assignment-submission-files/{fileId}/download-grant`; staged DELETE |
| `POST /api/v1/resource-uploads/presign` and lesson material `contentId/materialIndex` | Published content/lesson material DB row linked to its offering/delivery | Resolve the material record through the course API; read via its owner-scoped signed-grant endpoint. Author through course/lesson content service with teaching assignment or `courses.manage`. No generic presign response and no raw bucket lookup |
| `/api/v1/upload/*` for project files | `project_resource_files` by project UUID | `POST /api/projects/{projectId}/resource-files`, PUT, `POST .../{fileId}/complete`; GET metadata and `POST .../{fileId}/download-grant`; project-scoped PATCH/DELETE |
| Controller-backed lesson video `/upload/*` and play | `lesson_video_assets`, with optional linked `lesson_content` | `POST /api/courses/lessons/{lessonId}/videos`, PUT, `POST /api/courses/videos/{videoId}/complete`; learner GET `.../learner-videos`, then `POST /api/courses/videos/{videoId}/playback-grant` |
| Course images and video thumbnails previously stored in public folders | `lesson_video_assets.thumbnailStatus` for the supported thumbnail path | `POST /api/courses/videos/{videoId}/thumbnail`, PUT, `POST .../thumbnail/complete`. 5 MiB JPEG, PNG or WebP only; do not reuse the 10 MiB legacy thumbnail or course-image limit |
| `R2StorageUtils.getPublicUrl` and `ResourceFileController` GET or 15-minute signed URL | Feature-owned READY object row, checked under live scope | `POST` the matching feature `download-grant` (5-minute grant) on click; signed playback grant for a published, visible, authorized video. Never store or render a permanent public URL |
| `R2StorageUtils.listObjects` or raw `folder` search | SQL-backed feature metadata lists | GET the feature list with its deterministic parent, sequence and status order; database filters, never storage-bucket pagination |
| `/upload/import-file-from-url`, `/upload/import-video-from-url`, generic multipart proxy | None | Retired. Use a scoped local file selector or an approved HTTPS LINK content item; never make the server fetch a user-supplied URL |

## Browser upload and download states

1. Resolve a feature-owned UUID and eligibility **before** enabling the picker. Restrict each selector by `allowedMimeTypesFor`, `allowedExtensionsFor`, `acceptAttributeFor` and `validateStorageDeclaration` in `src/modules/storage/file-policy.ts` / `ui-models.ts`. Assignment/project documents: at most 50 MiB each; videos: at most 4,900 MiB, single PUT, no resumable upload; video thumbnails: at most 5 MiB. A folder label never overrides the feature's limit. Render a specific invalid-type/size message before network use.
2. `POST` the authorized feature grant with `originalName`, `contentType` and integer `sizeBytes`. Response contains the feature record ID, `method: "PUT"`, `uploadUrl`, `expiresAt` and exactly `requiredHeaders`. Show UPLOADING, with progress from XHR `upload.onprogress` for large files. **Do not** render, log or persist `uploadUrl`, its signed headers, bucket/object key or token. Only the short-lived in-memory transfer may use them.
3. `PUT` bytes directly to private R2, without browser cookies or additional headers, then `POST` that same record's `complete` route. A HEAD not yet visible (`STORAGE_UPLOAD_NOT_FOUND`) retries **completion** after a short bounded wait. Expired grants or failed PUTs retry **from step 2** with a fresh grant, not an old URL or cross-scope object.
4. Keep per-row status `UPLOADING`, `VERIFYING`/`PROCESSING`, `READY`, `FAILED`, `BLOCKED`/`QUARANTINED`, or `DELETED`. Only `READY` enables submit, file open, or video publish/play. A production scanner that is unavailable is NOT an excuse to mark a file READY. Never silently turn partially uploaded bytes into a submitted assignment.
5. On click, request the owner's or authorized reader's new signed read grant; show an explicit refresh/retry on expiry, 403 or changed object generation. For an old `contentId/materialIndex` deep link resolve parent and material index **within that tenant** first. A missing/forbidden record is 404 and must not probe R2 keys.
6. Faculty video managers require current teaching assignment to the chosen delivery, or college-admin `courses.manage`; project writes require mentor/admin within the project college; assignment writes require the active enrolled learner. Super-admin acting-college UI is **not** a write override. A new tab/window or retry repeats scope validation.
7. For private video playback, request the signed `playback-grant` only when learner enrollment, published content/video, visibility and READY state all pass. Use HTTP Range for seek; on `loadedmetadata`, resume to the provided time. Before URL expiry or after 403, request a new grant and restore playhead; continue persisting the approved progress record, not the signed media URL.

## Migration and operational gates

- `src/modules/storage/legacy-upload-workflow-model.ts` is the browser-safe crosswalk for the old payload names; `file-lifecycle.ts` implements scoped upload/read primitives and `file-access.ts` requires a feature-authorized resolver for old read modes. Neither can authorize access from a filename or folder alone.
- The production private bucket **must reject anonymous GET**. Do not cut over old publicly reachable originals until their owner-bound private replacements are attested, old public sources are removed or quarantined and their unsigned URL demonstrably returns 403/404.
- Live CORS validation requires R2 access and is an **unverified deployment gate**, not a passing test in this repository. Test real 100 MiB, 1 GiB and 4,900 MiB single PUTs with the exact signed `Content-Type` and metadata headers; check browser OPTIONS, timeouts and retry behavior. Do not claim transfer success without the signed complete/READY response.
- The preview/UI must distinguish `storage_not_configured`, external network failure, grant expired, incomplete transfer, scan pending, rejected content and out-of-date scope without exposing provider diagnostics or credentials. Actual provider settings and production malware scan must be separately attested.
