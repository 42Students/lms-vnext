- vNext entrypoint: `src/app/api/attendance/faculty/sessions/[scheduleEventId]/route.ts:1-38`, `src/app/api/attendance/faculty/route.ts:1-58`, `src/modules/attendance/faculty-service.ts:1-711` (authorization, roster, lifecycle, grading-window, attendance activity), `src/modules/attendance/faculty-marking-window.ts`, `faculty-correction-token-model.ts`, `faculty-correction-audit-model.ts`, `src/components/attendance/faculty-attendance-workspace.tsx:1-1291`, `src/db/schema/attendance.ts:1-171`; API scope: PATCH session with request JSON, separate GET roster and POST schedule.
- Scope includes old bulk attendance marking and its direct UI closure. The legacy process is deliberately **partial-success per learner** whereas vNext is **atomic full roster**; that is a behavioral difference, not automatically a quality regression. Structural/UI/authorization drift is audited separately from accepted architectural improvements. UNKNOWN requires live verification.
