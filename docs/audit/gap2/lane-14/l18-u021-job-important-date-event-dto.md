## Scenario acceptance matrix
- Two dates on same job same day (screening and interview), both with distinct types/labels: both show independent chips and details; no ID collision.
- Primary server dates response vs frontend job-importantDates fallback: same type-first classification, legend color and display label for type and dateType aliases.
- Typed event with misleading free-text label: classify from explicit type rather than label substring.
- Learner with targeted visible but unapplied job, then learner with applied closed job: both should see permitted important dates within window; never show unauthorized other-college jobs.
- Date at 00:10 IST and 23:59 IST, naive input and UTC `Z` input, all windows inclusive of intended local day; no off-by-one.
- Null, empty, whitespace label, invalid dates mixed with valid entries: skip bad item without hiding valid siblings.
- Event clicks show old job title, company, label, time, correct link; ICS export includes typed events without metadata leakage.
