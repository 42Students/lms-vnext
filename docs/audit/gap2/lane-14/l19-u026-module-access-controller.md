## Priority verification tests
- Mixed-college selection of 1 valid + 1 foreign learner, or 1 stale/locked among valid: old mutation must fail atomically, new partial writes are a confirmed behavior divergence. Define desired contract and fix both API and UI wording.
- 26, 100, and 1000 learner selection, repeated checkbox IDs, same/other college, academic-scope locked ancestor, and audit write failure; verify count and successful rollback.
- For each module including `courses` vs `electives` and `placements`, evaluate every scope (global/org/college/department/program/batch/class/learner) and both locked/unlocked/inherited states. Source currently disagrees on placement scope semantics.
- Full tree with zero stored overrides: old grid has all nodes while new stored-row grid omits them; add hierarchy-only nodes without inviting 10k learner rows in main list.
- Pixel compare badges, tri-state controls, lock icons, explanations, tables, dialogs and scroll under legacy shell at 1280/768/375. Backend alone cannot establish visual matches.
