# U020 — RefreshTokenBlocklist and JWT revocation

Static code audit 2026-10-21; no app code changed or tests run. The legacy JWT refresh model uses assigned JTI blocklisting on rotation/logout; `AuthController` consumes the repository, has a 10-second replay grace, and handles access-token JWT blocklisting. vNext intentionally replaces refresh/access JWT pairs with one opaque, random per-device cookie backed by HMAC digest, expiry and revocation. This is a security architecture change, not a missing equivalent JTI table. Old client refresh-route compatibility and cleanup are not yet verified.
