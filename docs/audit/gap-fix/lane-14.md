Legacy int course/parent/department IDs resolve through college-scoped `legacy_id_map` before UUID writes; no blind cast.

Lesson numeric courseId resolves by tenant through course -> offering -> path; historical period and cohort must be explicit. ## Packet 2–3 import and runtime distinctions

Legacy LessonContents.content_data may include material arrays, HTML and live session metadata. `legacy_content_data` stores the raw object without treating it as public file access: runtime materials still need storage keys plus ACL and optional existing separate material rows. Legacy content type `assignment` and `quiz` must be mapped to course_assignments / quizzes, not forced through lesson_contents shape check. Resource/ppt/pdf -> RESOURCE after validating notes/material storage; video/youtube -> corresponding kind; class/live links -> LIVE_CLASS only when both dates are valid, otherwise quarantined as unmapped metadata (do not fabricate an end timestamp). Legacy active/enabled should be recorded/translated separately from vNext DRAFT/PUBLISHED/ARCHIVED; draft means not learner visible regardless of enabled.

The historical `deadline_local` is a timezone-free India-local wall clock, not an instant; service must convert at API boundary only after identifying original timezone context. Legacy class-specific ordering should not mutate global `lesson_contents.sequence`; delivery/section keyed ordering requires a tenant-safe join table and CAS, deferred until authorization design. Hall/schedule historic text clocks and attendance_marked_at should be mapped under academics ownership.

Course overview heading/image/ordered takeaways are independent optional fields, preserving legacy meta_data. Short title was 64 chars and optional legacy code 40; existing vNext constraints remain 120/64, so the importer must surface collisions and never trim silently. Teaching role and year/semester are snapshots; effective permissions continue to come from delivery + membership. Old `is_deleted` must not be conflated with ending a faculty grant.

Retakes: vNext `attempt` already existed; 0203 replaces the pair uniqueness with a triple. A reset must acquire membership/content lock, select latest attempt, create next integer or update its own current attempt contract atomically. Until every read chooses latest attempt deterministically, 0203 stays unregistered. No project code/tests executed.
