## Integration fixture hardening

- `PROJ-HARNESS-22..28`: explicit current college, project roster, active user and `can_mutate` checks protect example SQL fixtures against accidental incorrect cross-tenant writes. This is fixture integrity, not proof of product route authorization.
- `PROJ-HARNESS-29..32`: real PostgreSQL index catalogue, restricted deletion semantics, `EXPLAIN (FORMAT JSON)` and savepoint rollback examples in `tests/integration/projects-placements-pg-harness-relations-chat17.test.ts`.
- **Unverified:** actual cloud execution of this new suite and browser keyboard/focus/visual viewport tests. Run `npm run test:db:projects-harness` on a migrated disposable `TEST_DATABASE_URL` and `npm run test:ux:kit:hardening` in CI; never report a suite as green merely because tests are checked in.

**Browser follow-up:** `UX-kit-HARDEN-35` now also has a real Chromium URL-parser witness in `tests/e2e/ux-safe-internal-href-chat17.spec.ts`, authored but not executed in the GitHub-only connector environment.

- **PROJ-HARNESS-33..35:** An in-memory fixture role claim previously could create a project or placement graph with a wrong-role or revoked author because the constructor only compared tenant IDs; the SQL schema permits these actors and would not automatically reject them. The harness now verifies active user, membership and role rows before writing, and `tests/integration/projects-placements-pg-harness-boundaries.test.ts` includes negative role/suspension examples. Commits `3322dd9d`, `384361bb`. Cloud PostgreSQL execution pending.

- **WEAK-tenant-domains-27:** Postgres 23505 may be nested beneath `DrizzleQueryError.cause`, so the earlier direct-code check could surface an implementation error on a genuine duplicate hostname race. A bounded, cycle-safe cause walker handles only code 23505; test covers nested duplicate plus cyclic unrelated error. Commits `92e30130`, `688e68c1`. Cloud unit testing pending.

- **PROJ-HARNESS-36:** Meeting fixtures permitted same-college active learners to be scheduling authors because the SQL guard only checked college/membership. The harness now requires a current active coordinator role; a real PostgreSQL wrong-role attempt must leave `project_meetings` unchanged. Commits `d7f43d53`, `4afe1160`. Runner pending.

- **UX-kit-HARDEN-37:** `FilterBar` previously called `window.matchMedia` unconditionally while opening the mobile filter overlay; WebViews without the API could crash the control. It now detects support and uses viewport width/resize fallback, removing listeners during cleanup. Test `UX-kit-HARDEN-37`; commits `3d05ec94` / `38bd19d9`. Browser runtime witness pending.

- **UX-kit-HARDEN-38 (S2, embedded WebView compatibility):** `ToastProvider` assumed `crypto.randomUUID()` exists for React keys. A restricted/legacy WebView could throw when announcing an error, hiding the very failure the user needs to see. Replaced with provider-local monotonic IDs; regression `UX-kit-HARDEN-38`, commit `061e31ff`. The browser harness explicitly removes `crypto.randomUUID` and checks success/error toast rendering. **Runner pending.**
- **UX-kit-HARDEN-39 (S2, overlay viewport recovery):** When `window.visualViewport` was absent, the shared overlay hook computed viewport height only on opening and did not respond to device rotation/resize. Added a window resize observer/listener with cleanup, preserving the existing visualViewport path. Regression `UX-kit-HARDEN-39`, commit `351b8ab8`. **Runner pending.**
- **UX-kit-E2E-01..03 (coverage acceptance):** A dev-only actual React UI-kit fixture and Playwright browser tests now cover dialog focus/escape, disabled tabs, scroll cue resize transitions, filter overlay with absent `matchMedia`, real file selection/clear/reselection and toast compatibility. This is an added regression gate, **not evidence that browser CI has passed**. Test route is deliberately 404 outside development.

- **PROJ-HARNESS-PLACEMENTS-12 (S1, test fixture lineage):** `createPlacementCandidateFixture` could accept a legitimate job ID paired with another drive's round ID in the same tenant, leaving application/round ancestry correctness to downstream constraints. It now verifies `placement_job_rounds.job_id` equals the persisted job before any application insert. A real PostgreSQL test forges a second drive's round and asserts no application rows are added. Commits `63bd760a`, `abb29439`, `d9620ea0`. Actual DB runner pending.

- **PROJ-HARNESS-38/39 (S1, fixture actor state):** A project fixture could accept a cached learner after organizational archival or membership-role revocation because the role and organization states weren't cross-checked at submission time. Joined currently active organization/college and persisted learner role; negative PostgreSQL tests assert no rows. Commits `a7810f28`, `2cbfe264`.
- **PROJ-HARNESS-40 (S1, composite task lineage):** Separate foreign keys on `project_task_submissions.project_id` and `task_id` do not establish that both identify the same workspace. Fixture now checks the persisted task's `project_id`, with an adversarial second project in the same college. Commits `8a16fd8a`, `6a09956e`.
- **PROJ-HARNESS-41 (S1, cross-workspace mentor scope):** The fixture previously allowed a same-college mentor who wasn't a member of the project to coordinate that project's meeting. It now requires an active writable project mentor roster, or an active College Admin role. Negative and recovery tests `PROJ-HARNESS-41` prove the intended fixture boundaries. Commits `9add0236`, `d8add99c`.
- **PROJ-HARNESS-42 (business-rule parity):** A project's final delivery is collaborative, not a per-learner private submission. The fixture intentionally permits a second active rostered learner to submit a teammate's draft, while denying outsiders and duplicate transitions; this matches production `submitProjectSubmission`. Regression `PROJ-HARNESS-42`, commit `43dd671a`.
- **PROJ-HARNESS-43 (S1, terminal state):** The fixture previously allowed draft creation and submission after project status `ARCHIVED` or `COMPLETED`, unlike production `submission-service.ts`. Closed projects now reject transitions. Database regression `PROJ-HARNESS-43` and unit contract `projects-pg-harness-contract-chat17.test.ts`. Commits `eb60c0b2`, `543cc7d5`.

All new PostgreSQL tests are committed, not yet reported green by the CI PostgreSQL runner. These changes guard the integration harness; route and service authorization must be tested independently.

- **UX-kit-HARDEN-45 (S1, mobile data minimization):** `DataTable` previously copied `mobilePriority: "hidden"` columns **without** `mobileDetail` into the phone-only `More details` disclosure, exposing fields explicitly marked hidden on mobile. The shared component now expands only secondary overflow fields and keeps restricted hidden columns absent from the disclosure. `UX-kit-HARDEN-45` checks the server markup; `tests/e2e/chat17-ui-kit-interactions.spec.ts` asserts real narrow-screen hidden/expanded state and legitimate desktop visibility. Commits `971f28bb`, `f68dbf2c`. Browser and unit runner pending.
- **PROJ-HARNESS-46 (S1, terminal project mutation):** The PostgreSQL fixtures previously allowed task submissions and project meetings on `ARCHIVED` or `COMPLETED` projects, although the corresponding production services reject terminal states. Now a shared status check prevents both while permitting recovery on active projects. `PROJ-HARNESS-46` includes rollback-only database witnesses and unit contracts. Commits `ed992e71`, `1d132db4`; DB runner pending.

- **UX-kit-HARDEN-47 (S2, upload screen reader validity):** `FileUpload` previously set `aria-invalid=true` whenever the native picker was merely disabled; a disabled control is unavailable, not a malformed user submission. It now marks invalid only when a file selection actually fails and retains the separate unavailable/size/type helper IDs. `tests/unit/UX-kit-states-chat17.test.tsx` verifies disabled and enabled forms. Commits `ea2c5c7c`, `b7fdb241`. Cloud runner pending.

- **UX-kit-HARDEN-48 (S3, disabled input affordance):** The native Switch correctly prevented interaction while disabled but retained the hand-pointer class on its label, suggesting it could be toggled. The disabled state now changes the pointer to `cursor-not-allowed`; `UX-kit-states-chat17.test.tsx` confirms the native disabled input, checked state, 44px target and style. Commits `b5ca6969`, `1c4785a0`. Runner pending.
