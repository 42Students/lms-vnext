## 1. Legacy behaviour (from code)

### 1.1 Entry points and host resolution
- `/login` renders `LoginPage` (`LFE/pages/login.js:1-19`). `/` renders the same login, or the JNTU or DGIPUC skin by host (`LFE/pages/index.js:11-64`). `src/proxy.js` makes `/login`, `/superadmin-login`, `/auth/handoff`, join, share, placements and marketing prefixes public (`LFE/proxy.js:15-34`). ## 4. Intentional differences (approved or clear improvements in vNext)
- One person is one user (decision: one human, many college memberships): no account chooser at login, the college is chosen after login or fixed by the host. Legacy `CHOOSE_ACCOUNT` lists, `choiceId`/key matching and `INVALID_CHOICE` have no equivalent, and need none.
- College tenancy by host with fail-closed unknown hosts; `Host` only (no `X-Forwarded-Host`); platform hosts listed in configuration (`request-tenant.ts:7-26`).
- Sessions in the database as device sessions (revocable per device, `/account/security`, "Sign out everywhere else"), revoked when a membership is suspended; legacy used JWT access and refresh tokens with a blocklist.
- Super Admin sign-in uses two independent factors (phone code and email code), in the same page, instead of the separate `/superadmin-login` with a Terms checkbox. Legacy relied on a configured phone allow-list.
- One shared 5-try budget per attempt for SMS and email, per-IP and per-contact send caps (5 / 8 / 20 per 10 minutes), same-origin check, constant-time code comparison, authorization re-checked when the code is consumed, single-use attempts (legacy allowed a 90 second replay).
- Recruiters can sign in on the platform host when they hold any college grant (legacy: only on the college's own address, error `RECRUITER_COLLEGE_ADDRESS`). Changes the recruiter phase-1 rule L9; keep unless the owner restores it.
- Branded college login: primary colour, desktop and mobile background images, support email and phone, Terms and Privacy links when configured (legacy tenant-bootstrap returned these but the page ignored them).
- Distinct session states with their own copy (`revoked`, `invalid`, `recent`, `access`), `MembershipRecovery` page for a membership that became inactive, and a signed-in devices page.
- 500 page also offers `Try again`; both error pages are accessible links and buttons with 44 px targets.
- Phone input accepts any E.164 number as well as 10-digit Indian numbers.
- Test OTP codes exist only when `APP_ENV=development` (`AuthConfig`), no localhost-only bypass paths.
- The e2e sign-in page is replaced by e2e identity cookies guarded by a secret (`V/auth/e2e-identity.ts`).
