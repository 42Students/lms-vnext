## 4. Intentional differences (vNext improvements or approved deviations)

- Issues are read and triaged only by authenticated Super Admins; engineering notes and attachment keys are never exposed through a public list, and screenshot metadata does not leak private object keys. The disabled "Report issue · pending reporter auth" item records the owner-facing blocker (reporter-session migration).
- Workflow changes use optimistic `version` checks and write immutable activity rows; Audit Findings status changes are audited and version-checked (`audit-finding-status-action.tsx`).
- Audit findings CSV export of the filtered page and extra filters (account role, resolution, retest, production verified, exact issue type, IST date range) exist only in vNext.
- Tracker pages sit inside the app shell with the standard dark / light theming instead of the standalone `TrackerShell` (theme toggle and skip link replaced by the shell equivalents; UNCONFIRMED parity of the skip link).
- Known Errors store durable signatures with occurrence counts and distinct affected accounts; live Cloud Logging search and Telegram alerts are explicitly separate integrations (BLOCKED items, not claimed).
- Feature flags: the tracker and logs pages show "not enabled" notices until the DB10 flags and migrations are verified; this is environment gating, not a gap.
