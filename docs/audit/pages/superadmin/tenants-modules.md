## 4. Intentional differences (improvements or approved deviations; no decision file found unless stated)

- Tenant directory (`/admin/tenants`) with college search, organization and ACTIVE / ARCHIVED / ALL filter, pagination, CSV export (`TenantDirectoryCsvControl`, `src/modules/colleges/admin-tenant-export-model.ts`) and a detail page; legacy has only the in-page tables. Keep.
- Archive instead of hard delete with a dependency-count dialog (memberships, departments, academic periods, project assignments, projects, placement relationships, seasons, jobs, tenant domains) rather than a generic sentence; soft-delete is also the legacy behaviour. Keep.
- College code and organization are immutable after create (`college-edit-dialog.tsx:99`). Legacy lets both change although its own help says avoid changing the code. Treated as an improvement; owner confirmation not found in `docs/decisions/*` (UNCONFIRMED).
- Readiness has 10 persisted checks across lifecycle, academics, people, placements and domains, CSV export and status / area filters; legacy only checks domains, logo and a union of departments / faculty / students. Keep (see gap 23 for what legacy has that vNext lacks).
- The prod-style Tenant Domains manager (multi-host, DNS TXT verification, make primary with consequence text, typed confirmation for deleting the primary) and the `/admin/domains` route exist in vNext; dev legacy removed the panel (only prod-2026 has `TenantDomains.js`). Keeping it is a superset of dev; whether to keep it alongside a subdomain allot (gap 20) needs an owner decision.
- Mobile: tenants, colleges and organizations render as cards below `lg` (`A/admin/colleges/page.tsx:120-147`) instead of horizontally scrolling tables.
- Overview unscoped shows live Organizations and Colleges counts; legacy platform view has no numbers.
- Sidebar `Module Access` opens a college directory when no college is scoped instead of an info alert (legacy needs a college in the header).
