## 1. Legacy behaviour

### 1.0 Entry, shell, roles
- Route `/college-admin/attendance` (`LFE/pages/college-admin/attendance.js`) renders `LFE/pages/superadmin/sections/Attendance.js` inside the Academic Setup shell (tab 10 of 10, no step banner). Roles ADMIN and SUPER_ADMIN; a super admin must pick a college first (Alert `Select a College to view attendance`, `Attendance.js:476`). A college admin with no college sees the shell warning `Admin not assigned to a college` (see `academic-setup.md` 1.0).
- Header (`Attendance.js:470-475`): H1 `Attendance`, subtitle `Review monthly attendance by class and course, correct recent records, and export the same grid shown on screen.`

### 1.1 Policy card (`Attendance.js:477-486`, `LFE/components/admin/PolicySettingField.js`)
- Card `Attendance policy` with two fields: `Late marking allowed for` (key `attendance.correctionWindowHours`, default 24, min 1, max 168, suffix hours, help `How long after a class ends attendance can be marked or corrected.`) and `Minimum attendance` (key `attendance.eligibilityThresholdPercent`, default 75, 1 to 100, suffix %, help `Shown to students, and used here to flag students below it. It does not block anyone from exams.`).
- For a college admin (`userType FACULTY` and `facultyType ADMIN`) both fields are READ-ONLY with a `Read-only` tag, a reload button (`Reload {label}`), text `Loading policy…` and the server error text if the load fails (`PolicySettingField.js:55-150`). Reads use `GET /api/v1/admin/attendance/policy?collegeId=` (`LBE/controller/AdminAttendancePolicyController.java`). Editing, `Save`, and `Reset to default` exist for the super admin only (`PUT/DELETE .../superadmin/tenant/settings/college/{id}/{key}`).
- The minimum-attendance value feeds the grid: student percent tag is red below it, orange within 10 points above it, green otherwise (`Attendance.js:211-214`).

### 1.2 Pickers (`Attendance.js:497-522`)
- `Select attendance class` (placeholder `Select class`, or `Classes unavailable` on failure; searchable; width 220). Elective sections named `[Elective] Course · Slot` are shown as `Course · Slot (elective)` (`:334-337`).
- `Select attendance course` (placeholder `Loading class courses…` / `Class courses unavailable` / `No courses linked to this class` / `Select course`), disabled until a class is chosen. Options come from the class's teaching assignments (`GET /teaching-assignment/byClass/{classId}`), labelled `{course} · Sem {n}` plus ` · past` for inactive assignments, active and latest semester first (`:376-396`). Link button `Show all college courses` / `Only courses taught to this class` widens to every college course (`:514-517`). A class switch clears the course.
- Month stepper: buttons `Previous month` / `Next month` and a `MMMM YYYY` label (no direct month input). Button `Export CSV` (disabled with no rows).
- Errors: Alert `Couldn't load classes/courses for this college` with `Retry`; Alert `Couldn't verify which courses are taught to this class` with `Retry class courses` (course select stays disabled); load failure Alert `Couldn't load attendance data.` with `Retry`, or `Couldn't refresh attendance` + `Showing the last attendance loaded for this class, course and month.` when a grid is already on screen; `Refreshing attendance…` status. Empty `Pick a class and course to view attendance`; empty grid `No attendance data for this class, course and month`. Skeleton `Loading monthly attendance`.

### 1.3 Summary and grid (`Attendance.js:34-280`)
- Summary region `Monthly class health`: big percent (`—` when nothing marked), sentence `{n} present marks across {m} marked sessions.` / `Sessions were held, but no attendance has been marked yet.` / `No sessions have been held this month.`; stat chips `Students`, `Sessions held`, `Absences`, and an amber `Not marked` count when held sessions have no attendance.
- Card header `Monthly Attendance` / `Review attendance day by day; open any held session to inspect and correct it.` with chips `Active days` and the month. Legend: `P = Present`, `A = Absent`, `N = Held, attendance not marked`, `✖ = No class`, `2/3 = sessions attended; open to choose a session`.
- Table: one row per student (`Student Name`, sticky corner), ONE COLUMN FOR EVERY CALENDAR DAY of the month (weekday initials above, Sundays shaded), last column `% month` (tooltip `This month, marked sessions only. Exam eligibility is judged on the whole semester.`). Cell: `✖` no class; `N` held but not marked; `P`/`A`; `x/y` when several sessions in the day. Future sessions are not counted ("held" = started). Caption for screen readers, per-cell `aria-label`s.
- Clicking a cell of a held session opens the record; a day with several sessions first opens modal `Choose a session — {student}` (text `Only the session you open will be corrected; other sessions remain unchanged.`, one button per session `{title or date} · {time} · Absent|Present|Not marked`).

### 1.4 Record modal and correction (`Attendance.js:239-278`; `LBE/controller/AdminAttendanceController.java:206-342`)
- Modal `Attendance — {student} — {session}`: loads `GET /api/v1/admin/attendance/record?collegeId&studentId&classScheduleId` (skeleton `Loading attendance record`; failure Alert `Attendance record unavailable` / `No attendance status can be inferred from this failure. Corrections are disabled until the record loads.` + `Retry record`; incomplete payload `The attendance record is incomplete. Retry before correcting it.`).
- Descriptions: `Session`; `Current state` (red `Absent` or orange `Excused`/`Medical`/`Late`; gold `Not marked yet`; green `Present`); when absent, `Marked by` (name or `Not recorded`) and `Marked at` (formatted UTC, `—` if none).
- Absent record: button `Mark present` (`POST /mark-present`, deletes the absence row). Present record: radio `Absent` / `Excused` / `Medical` / `Late` under `Mark absent, optionally with a reason:` and a danger `Mark absent` button (`POST /mark-absent?status=`; unknown status rejected `status must be one of EXCUSED, MEDICAL, LATE (or omitted for a plain absence)`).
- Success toast `Attendance corrected for {student} — {session}.`, modal closes, grid reloads; failure toast = server message or `Attendance correction failed. Retry without closing this record.`. Only one correction at a time (ref lock).
- Backend (`:168-175,272-342`): the retroactive-marking window is BYPASSED for admins ("the whole point of an admin correction tool is fixing attendance after that window has closed"), the class schedule must belong to the admin's college (`requireClassScheduleInScope`), the marker id and reason are stamped on the row, and the audit events `ADMIN_ATTENDANCE_MARK_ABSENT` / `ADMIN_ATTENDANCE_MARK_PRESENT` are written (collegeId, studentId, status).

### 1.5 Export (`Attendance.js:447-467`)
- `Export CSV` file `attendance-class-{classId}-course-{courseId}-{YYYY-MM}.csv`; columns `Student`, then `1`..`N` (one per calendar day); cells blank (no class), `N`, `P`, `A` or `x/y` exactly as on screen; no percent column.

## 2. vNext behaviour

### 2.0 Routes and guards
- `/college/attendance` (`V/app/(authenticated)/college/attendance/page.tsx`): resolves the college from the membership (or the super admin's selected scope); with none it throws `Select an active college to view attendance.` (generic error boundary `error.tsx`). Query `deliveryId|sectionId|courseId|allCourses|month` is zod-validated (`:36-42`); an invalid value raises a validation error page rather than a message.
- `getAdminAttendanceOptions` / `getAdminAttendanceGrid` / `correctAdminAttendance` (`V/modules/attendance/admin-service.ts:59-661`) require the `academics.manage` permission in the college (`:109-115`) and a delivery that belongs to it.
- Header: eyebrow `College Admin · Academics`, title `Attendance`, description `College-wide attendance oversight for {college}, including unmarked sessions and admin corrections.` and three links: `Attendance by Department`, `Correction windows`, `Attendance policy`.

### 2.1 Workspace (`V/components/attendance/admin-attendance-workspace.tsx`)
- Two read-only cards `Retroactive marking window` ({n} hours) and `Minimum attendance` ({n}%), notes `Read-only policy. Corrections are allowed from session start until this many hours after session end.` and `Learners below this marked-session percentage are highlighted.`
- Form: `Class` select (`{name} · {code}`), `Course` select (`{code} · {name}`, `(not taught to this class)` suffix) and checkbox `Show all college courses (including courses not taught to this class)`, `View attendance` submit; `Previous` / `Next` buttons plus a native `month` input. State is in the URL.
- Empty states: `No assigned class courses`, `Select a class and course`, `Course is not taught to this class`, `No active learners in this class`, `No attendance data for this month`.
- Summary: `Monthly class health` card showing `{class} · {course}` and `{marked} of {held} held sessions marked`, `Export CSV`.
- Grid: one column per session DAY that has sessions (`DD Mon`, `N sessions` for multi), not per calendar day; learner column (name + `Roll {n}` or email), final `%` column (error under threshold, warning within +10, else success). Cell codes `P A E M L`, `—` not marked, `S` scheduled (future) (`admin-grid-model.ts:60-85`); multi-session days show `{n} sessions` and open a chooser drawer `Choose attendance session`. Legend line below.
- Correction drawer `Attendance — {learner}` with the session and time, `Current status`, note, `Marked by`, `Marked at`, and buttons `Present`, `Absent`, `Excused`, `Medical`, `Late` (disabled outside the window). `window.confirm("Mark {name} {status} for {session}? This change is recorded.")` precedes a `PATCH /api/attendance/admin/sessions/{id}`. Errors are shown in the drawer (`The session has not started.`, `The correction window has expired.`, server message or `Attendance correction failed...`). On success the drawer closes and the page refreshes; no success message.
- `correctAdminAttendance` (`admin-service.ts:425-661`): roster membership check, row-locked event, REQUIRES `facultyAttendanceMarkingWindow` to be `OPEN` for College Admin as well (`:504-524`), PRESENT deletes the exception row, other statuses upsert it with `markedByUserId` and `markedAt`, and the session row is created/updated as `MARKED`. No activity/audit event is written (`grep activity admin-service.ts` has no match; the faculty path records `COURSES_ATTENDANCE_MARKED` at `faculty-service.ts:631`).
- CSV export (`:292-336`): browser-built file `attendance-{sectionCode}-{courseCode}-{YYYY-MM}.csv`; columns `Learner`, `Roll`, one column per session (`YYYY-MM-DD HH:MM`), `Attendance %`; cells use the full labels (`Present`, `Not marked`...); formula-injection safe (`attendanceCsvCell`).

### 2.2 Other vNext pages
- `/college/attendance/settings` (`attendance/settings/page.tsx`, `college-attendance-policy-form.tsx`): College Admin can EDIT both numbers (threshold 1-100, window 1-168) with `PUT /api/attendance/admin/policy` (same-origin check); no activity event is written by `updateCollegeAttendancePolicy`.
- `/college/attendance/corrections`: read-only list of scheduled sessions in an IST date range (max 31 days, 250 rows) with `Faculty window` status; it states that no correction-request table exists.
- `/college/attendance/departments`: per-department marked sessions and explicit status counts, search, 25 per page, `Export CSV` (`/api/attendance/admin/departments/export`); it states explicitly that these are "not attendance rates".

## 4. Intentional differences (keep)

- Roster and sessions come from persisted section schedule events and an active-membership roster check (locked row) instead of the legacy class/learner tables; corrections are transactional and lock the event row.
- Students are shown with a roll number or email, and the CSV neutralises spreadsheet formulas.
- The three extra pages (`Attendance by Department` + CSV, `Correction windows`, `Attendance policy` edit form) are vNext improvements; the link from Attendance to the department report was added in merged work.
- Month and class/course selection are URL state, so a view is shareable and survives refresh.
