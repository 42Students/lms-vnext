# College Admin / Course tabs  (legacy: /college-admin/lessons, /lesson-content?type=video|resources|live-classes, /assignments, /quizzes, /course-progress; vNext: /college/lessons, /videos, /resources, /live-classes, /assignments, /quizzes, /course-progress)
Audited: 2026-10-16 by Claude Sonnet 5.5 (Round A, read-only)   Reviewed: not yet (Round R pending)

Page slug `course-tabs`, account College Admin, gap IDs `COL-course-tabs-NN`. Sibling files: `courses-content.md` (Courses, Course detail, Faculty Assignment; its gap COL-courses-content-16 hands these seven tabs to this file), `academic-setup.md`, `people.md`, `dashboard.md`, `attendance.md`, `placements.md`, `projects.md`, `verification-misc.md`. Evidence abbreviations: `LFE/` = legacy frontend `_hr-tpo-fe\src\` at lms-dev-2026 63fea105, `LBE/` = legacy backend `_hr-tpo-be\src\main\java\com\_42students\lms\`, `V/` = vNext `src\` at main. Already-merged work (grouped sidebar, `Courses & Content` strip, `Companies`... not relevant here) is not re-reported.

Headline finding: in legacy every one of these seven tabs is a working management screen (create, edit, delete, reorder, publish, grade, export). In vNext five of the seven are explicitly READ-ONLY catalogues ("Read-only ... oversight; course authoring and review remain in their offering workspaces") and the offering workspace only lets an admin create a learning path and lessons and publish/archive items that already exist. The College Admin therefore cannot author videos, resources, live classes, assignments or quizzes at all, and cannot grade.

## 1. Legacy behaviour

### 1.0 Shell shared by all tabs
- Group strip `Courses & Content`: `Courses`, `Lessons`, `Video`, `Resources`, `Live Classes`, `Assignments`, `Quizzes`, `Progress` (`LFE/common/navGroupDefinitions.js`; `Video`/`Resources`/`Live Classes` all open `/college-admin/lesson-content?type=video|resources|live-classes`). Contact your administrator.` (`LFE/pages/college-admin/lesson-content.js:19-30`; other pages use the same pattern with their own noun).

## 2. vNext behaviour

### 2.0 Common
- Every page requires a membership (`if (!context.membership) redirect("/dashboard")`, e.g. `V/app/(authenticated)/college/lessons/page.tsx:13-14`), is read-only, uses GET filters validated by zod (invalid input shows `Invalid ... filters` with a clear link), pages 25 at a time and links each row to `/college/courses/offerings/{offeringId}`. Eyebrow `College Admin · Courses & Content`.
- Write capability for a College Admin lives only on the offering page (`V/components/courses/admin-offering-learning-overview.tsx`, `admin-learning-structure-actions.tsx`): create/edit/publish/unpublish/archive a Learning Path, create/edit/archive a Lesson (name, description, order), move a lesson up/down with confirm, publish/archive an existing content item (`:60-68`), publish/hide quiz results of a CLOSED quiz (`AdminQuizResultsActions`). There is no create form for videos, YouTube items, resources, live classes, assignments or quizzes for an admin; content authoring is the Faculty workspace (`faculty-lesson-authoring.tsx`, `faculty-content-editor.tsx`, `faculty-assignment-editor.tsx`, `faculty-choice-quiz-builder.tsx`).

### 2.1 Lessons (`college/lessons/page.tsx`, `V/components/courses/college-learning-directory.tsx`, `V/modules/courses/college-learning-directory-service.ts`)
- Title `Lessons`, description `Read-only lesson catalogue across college course offerings and learning paths.` Two links above the card (`Export filtered lessons CSV`, `View college live classes`), header action `Course offerings`.
- Filters: search `Course or lesson` plus a large set of exact-code and state filters (course/program/batch/period codes, statuses, content presence, sequence range, content counts, audience, evidence flags). Table `Lesson / order`, `Course / offering`, `Learning path / lesson state` (`Path: X; Lesson: Y`), `Content records` (`N published / M authored`, flagged-visible count, link `View recorded course activity`). 25 per page, previous/next only.

### 2.2 Video and Resources (`college/videos`, `college/resources`, `college-content-aggregate.tsx`)
- Titles `Video Content` and `Resources`; description "Read-only catalogue of registered VIDEO and YOUTUBE lesson records. Playback and stored file access are not provided here." and "...RESOURCE records. Private attachments and external links are not exposed here." Filters by title, course/program/batch/period code etc. Table `Content`, `Course / cohort`, `Lesson / learning path`, `Scope` (shared or section), `State` (status plus a `Show to students`/`Hide from students` button with confirm and stale-version protection via `PATCH /api/courses/college-content-visibility`). Mobile card list below 640px. Footer: "Content creation, revision and publication remain in the offering workspace."

### 2.3 Live Classes (`college/live-classes`, `college-live-classes-directory.tsx`)
- Title `Live Classes`, description "Saved lesson sessions in your college. Meeting links are available only through authorized course workspaces." Date-range/view filters, cards with title, time, course link; no meeting link, no Join.

### 2.4 Assignments and Quizzes (`college/assignments`, `college/quizzes`, `college-assessment-aggregate.tsx`, `V/modules/courses/college-assessment-aggregate-service.ts`)
- Titles `Assignments` / `Quizzes`; description "College-wide persisted ... Read-only oversight; course authoring and review remain in their offering workspaces." Filters: title search, status, exact course/program/batch/period codes, scope, due presence/window, results (quizzes). Table `Assignment|Quiz` (title, `Maximum N points`), `Course / lesson`, `Scope`, `Status` (+ `Results published|hidden` for quizzes), `Due (IST)`, `Submissions|Attempts` (a single persisted-row count). No export, no per-row actions.

### 2.5 Progress (`college/course-progress`, same directory component)
- Title `Course Progress`, description "Persisted learner content activity by offering. Not a course-completion rate or academic eligibility report." Table `Course / offering`, `Offering state`, `Recorded learner activity` (`N completed content records of M; K distinct learners with records`), link `View authored lessons`; CSV `Export recorded course activity CSV` (offering-level). No per-learner view, no class selector.

## 4. Intentional differences (keep)

- Offering-based model: lessons belong to a shared Learning Path of a Course Offering, and content may be shared or section-specific; the catalogue pages join to the offering so the admin can jump to the right workspace (`/college/courses/offerings/{id}`).
- Archive instead of delete for lessons and content; stale-version protection and a confirm on the visibility toggle; lesson order edits carry `expectedSequence` (optimistic concurrency).
- Strict, validated filter queries with a "clear filters" recovery, and a much richer filter set (codes, evidence flags, sequence ranges) plus a filtered Lessons CSV, which legacy does not have.
- The catalogue pages never return storage keys, signed URLs, answers or learner contact data (privacy by default), which is why COL-course-tabs-17 needs a deliberate admin-scoped preview rather than raw links.
