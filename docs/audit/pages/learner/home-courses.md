## 1. Legacy behaviour

### 1.0 Entry points, roles, routing
- Learner home is `/learn/courses` (`LFE/config/roles.js:30`: LEARNER portal `/learn`, home `/learn/courses`). `/learn` only 302-redirects to `/learn/courses` (`LFE/pages/learn/index.js:1-6`). There is **no learner dashboard page** in legacy: the course list is the landing page.
- Sidebar item `Courses` (`/courses`, group `learning`, `LFE/common/lists.js:55-65`). Course tabs for a learner (`courseTabList`, `lists.js:271-309`): `Overview` (home), `Learning Path` (roadmap), `Attendance` (attendanceDetail), `Discussions` (discussions). `Blueprint` and `Students` are Faculty/Admin only. There are no separate Assignments, Quizzes, Grades or Progress tabs: assignments and quizzes live inside Learning Path, grades are published inside the assignment/quiz item.
- Course route `/learn/courses/{slug-or-numeric-id}/{tab}`. The bare route client-redirects to `/home` keeping the query (`LFE/pages/learn/courses/[courseId]/index.js:22-37`); an unknown tab `router.replace`s to `/home` (`[...courseTab].js:101-108`, `VALID_TABS` L17); a numeric id is rewritten to the slug once the course loads (`[...courseTab].js:72-79`, `utils/learnerCourseDetail.js:280-288`).
- Roles: LEARNER and SUPER_ADMIN pass the edge guard (`LFE/proxy.js`, `config/roles.js`). Backend list/semesters need `requireAccessLearner(principal, studentId)` (`LBE/controller/StudentCourseController.java:43,77`): a learner reads only their own id.

### 1.5 Discussions tab (`Classroom/classroom.js`, backend `ClassroomController`/`ClassroomServiceImpl`)
- Subtitle `Keep course conversations in one place and follow along easily.` Scope needs course id + class id; otherwise `Discussion unavailable` / `This course is not linked to one of your classes yet, so there is no discussion to show.` (L495-501).
- Feed: day separators (`Today`, `Yesterday`, long date), sender groups (same sender within 5 minutes collapse), avatar initials with a deterministic tint per sender, name (`You` for own), `Faculty` tag, relative time (`Just now`, `5m ago`, `3h ago`, `2d ago`, then date; tooltip full date), `Pinned` tag; newest at the bottom, lands on newest; `N new message(s)` jump button when scrolled up; pinned strip `Pinned by {name}` with `· 1 of N` (L570-597). Faculty can pin/unpin (learners cannot); own messages and faculty can delete.
- Polling: every 15 s (platform tunable `ui.chatPollIntervalMs`) while the tab is visible, asking only for changes since the newest `updatedAt` (deleted rows arrive as tombstones) (L23-26,203-274; `ClassroomController.java:30-48`, `ClassroomServiceImpl` `fetchMessagesChangedSince`/`withoutDeletedContent`).
- Composer: persistent hint `Have a doubt about anything in this course? Feel free to ask here.`, textarea `Write a message...`, max 4000 chars (counter after 3400), button `Send`, hint `Enter to send · Shift+Enter for a new line`; unsent draft protected by `beforeunload` and a route-change confirm `Discard your unsent discussion message?` (L281-302). Errors: `Failed to post message.` (or server text), `Failed to delete message.`, `Failed to update pin state.`; refresh failure keeps old messages with the alert `Discussion refresh failed` / `Could not refresh the discussion. Showing the last messages we loaded.`; initial failure `We could not load this discussion.` / `Check your connection and try again.` with `Retry`. Delete confirm (antd Modal): title `Delete this message?`, text `This cannot be undone.`, `Delete`/`Cancel` (L373-399).
- Backend rules: text trimmed, empty -> 400 `Message cannot be empty`, `@Size(max=4000)` (`ClassroomMessageCreateDTO`); a message is owned by role+id (learner 21 is not faculty 21, `ClassroomServiceImpl.deleteMessage`); pin only faculty/admin (`Only faculty or admin can pin messages`); learner access via `requireAccessCourse` + `requireAccessClass`.

## 4. Intentional differences (vNext improvements or deliberate deviations)
- Past-semester courses stay openable read-only with a `Past semester` badge, `Term access` filter and read-only discussion/progress; legacy blocked them with `Not your current semester: shown for reference` (`docs/parity/learner.md:179`, "Historical semester courses remain browseable and are explicitly read-only").
- Extra list tooling: progress filter, sort, `Continue learning only`, `Clear Course filters`, per-card progress bar, overdue note, last activity, next due, overdue/next-item shortcut buttons, course code strip.
- Extra Overview content: learning-path preview, four metric cards, explicit "progress not measurable" notice, mobile jump nav; extra routes `Detailed progress` and `Attendance history` (`/progress`, `/attendance-summary`).
- Attendance: IST-fixed month logic, extra statuses (Late/Excused/Medical), unmarked sessions excluded with an explanation.
- Discussions: per-message `Reply`, paged history (`Load earlier messages`), highlighted pinned message, desktop-only Enter-to-send (touch keyboards keep Enter as newline).
- Routing by delivery id (section+course) instead of course slug; elective courses are real deliveries.
- Security hardening: HTTPS-only authored links, tenant-scoped reads on every route, no course data returned to non-members.
