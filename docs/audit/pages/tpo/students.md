### 1.2 Data: `GET /api/v1/tpo/students/table` (exact fields; this is the endpoint the batch grid also uses)
Controller `HUB.table` (HUB:57-62): query `everyone` (default false). `everyone=false` (Students page) keeps only learners whose resolved placement decision is ELIGIBLE (SRS:107-108); `everyone=true` (batch Students tab, pickers) returns every live learner of the college. Response `{ students: [...], counts: {ALL, NOT_REGISTERED, REGISTERED, NOT_READY, UNPLACED, PLACED, HIGHER_STUDIES, DEBARRED} }` (SRS:167); `counts` skip finished batches (SRS:156-164) and the Students page ignores them (`counts={() => null}`, IDX:272). Rows ordered `first_name, last_name` (SRS:88). Deleted learners excluded (SRS:87). Learners with no class/batch are included (LEFT JOINs, SRS:84-86).

Row fields, in the order they are produced:
- From SQL (SRS:62-83): `learnerId, firstName, lastName, rollNumber, branch` (= learner.department), `email` (contact_mail), `phone` (contact_mobile), `hasResume` (bool), `cgpa, academicSource, batch` (academic-record columns), `profileComplete` (overwritten below), `registration` (latest placement_registration.choice, else `PLACEMENTS` if the learner has any application, else null), `applications` (non-deleted count), `offers` (status RELEASED or ACCEPTED), `gender, dob, hasGithub, hasLinkedin, hasPortfolio, skillsCount, certificationsCount, projectsCount, experienceCount`, `classId, className, batchId, batchName, batchEndDate, programId, programName, offersWaiting` (status RELEASED), `batchInvitedAt` (placement_batch.invited_at). Removed after use: `placedOffers`, `activeDebarments`, raw `skillNames`, `codingProfilesRaw`.
- Derived per row (SRS:109-165):
  - `status`: DEBARRED > PLACED > (registration in HIGHER_STUDIES / ENTREPRENEURSHIP / COMPETITIVE_EXAMS / NOT_INTERESTED) > REGISTERED (registration PLACEMENTS) > NOT_REGISTERED (SRS:113-115).
  - `profileComplete` bool (marks: 10TH and UG and (12TH or DIPLOMA), SRS:123-125); `readiness` READY / NEEDS_WORK (1 gap) / NOT_READY; `readinessNote` ("Ready" or gaps joined " · ": "No resume", "Academics incomplete", "No prep tests yet", "Prep tests NN%"); `prepAverage` (rounded %, only when the college chose prep courses; otherwise the key is absent) (SRS:117-133,138).
  - Outcome block (PlacementOutcomeService.Outcome.toMap): `outcome` (PLACED_ON_CAMPUS, PLACED_OFF_CAMPUS, HIGHER_STUDIES, ENTREPRENEURSHIP, COMPETITIVE_EXAMS, NOT_INTERESTED, SEEKING, DEBARRED, NOT_REGISTERED), `outcomeName`, `outcomeLabel` (college's own label), `outcomeDetail`. Order: placed on campus, placed off campus (external_placement), the registration choice, debarred, seeking (PLACEMENTS or any application), not registered.
  - Marks block (AcademicMarksService.marksFor, merged by `putAll`, SRS:137): `marks` {`10TH`,`12TH`,`DIPLOMA`,`UG`,`PG` each `{shown, pct, converted, verified}`} (verified/imported value first, else the student's own Education entry with `verified:false`), `degree` ("B.Tech · CSE"), `qualifyingExam`, `passingYear`, `passingYearVerified`, `gapYears`, `cgpa` (verified, else own UG CGPA out of 10; key present only when known), `cgpaVerified`, `marksVerified`, `twelfthLevel` (12TH or DIPLOMA, same rule as drive eligibility), `lateralEntry`. A learner with no marks gets `marks: {}`.
  - `skills` (list of names, trimmed, unique), `codingPlatforms` (keys of LEETCODE, HACKERRANK, CODECHEF, CODEFORCES, GFG, HACKEREARTH that have a username), `profileStatus` (VERIFIED / PENDING / SENT_BACK / INCOMPLETE, `ProfileVerificationService.profileStatuses`), `waitingSections` (subset of EDUCATION, IDENTITY with status SUBMITTED or UPDATE_PENDING), `offersWaiting` (int), `debarred` (bool: active debarment = not lifted and (until_date null or >= today) and (until_date set or until_drives null or drives_counted < until_drives)).
  - Eligibility block (PlacementEligibilityService.Resolved.toMap): `eligibility` (ELIGIBLE / INELIGIBLE / NOT_DECIDED), `eligibilityLevel` (LEARNER / CLASS / BATCH / null), `eligibilityReason`, `eligibilityNote`, `eligibilityBy`, `eligibilityAt`. `batchFinished` bool.
  - `stage`: PLACED, else VERIFIED (registered and profileStatus VERIFIED), else REGISTERED (registration PLACEMENTS or placed), else INVITED (batchInvitedAt set), else ELIGIBLE (SRS:150-152).
  - `journey` (up to 20 entries, newest application first) and `best` (deepest entry, newest wins a tie) (SRS:199-242): entry = `{jobId, company, role, depth 0-5, outcome (APPLIED/IN_PROGRESS/CLEARED/WAITLISTED/NOT_SELECTED/WITHDRAWN/OFFERED/PLACED), round, label}`; labels "Placed", "Offered", "Not selected [at R]", "Cleared R", "Waitlisted [at R]", "Withdrew", "In R", "Applied" (`StudentJourneyRules.label`). Only outcomes are read, never panelist comments.
  - Booleans/ints normalised: `hasGithub, hasLinkedin, hasPortfolio` bool; `skillsCount, certificationsCount, projectsCount, experienceCount` int (SRS:153-154).
- Panel endpoint `GET /tpo/students/{learnerId}/detail` (HUB:64-69, SRS:291-331): `row` (the same row as above for this learner, built with `eligibleOnly=false`), `profile` {learnerId, firstName, lastName, rollNumber, branch, email, phone, resumeUrl, linkedin, github, portfolio, codingProfiles[{key,label,username,url}], cgpa, academicSource, tenthPct, twelfthPct, diplomaPct, ugPct, gapYears, passingYear, batch}, `applications[]` {applicationId, jobId, jobTitle, companyName, stage, appliedByCollege, withdrawalReason, appliedAt, stageChangedAt, offerId, offerStatus, ctcLpa}, `notes[]` {id, note, createdBy, createdAt, createdByName} newest first, `history` (audit events for STUDENT, 100), `prep[]` {id, courseId, courseName, dueAt, assignedAt, total, done}, `debarments[]` {id, reason, untilDate, untilDrives, createdAt, liftedAt, liftedReason}, `registration[]` (latest {choice, source, consentAt, outcomeLabel, outcomeDetail}), `requests[]` (all requests of the learner, pending and decided, `requestsQueue` rows, SRS:668-683). A learner of another college returns "Not found" (`TpoAccessGuard.requireLearner`).
- Supporting reads: `GET /api/v1/choices` (field `outcomeLabels`: college labels under HIGHER_STUDIES / ENTREPRENEURSHIP / COMPETITIVE_EXAMS / NOT_INTERESTED; `ChoicesController.java:56`, `PlacementOutcomeService.labels`), `GET /tpo/drives` (drive pickers), `GET /tpo/students/prep-courses` (courses of the caller's organisation, max 500, SRS:693-696), `GET /tpo/students/requests-queue?includeDecided&decidedDays` (HUB:220-226; default 30 days, `decidedDays<=0` = all; LIMIT 500; pending first).

- History page: round result versions (STAGED / SUPERSEDED / APPLIED) and joining outcomes shown per application with IST timestamps; legacy shows only the furthest outcome.
- The Debar control refuses to overwrite an unrelated Ineligible override instead of silently replacing it.
