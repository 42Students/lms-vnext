## 4. Intentional differences (improvements or approved deviations; no decision doc cited unless stated)
- Optimistic concurrency: request decisions send `expectedUpdatedAt` and verification decisions send the row version (`expectedVersion`), instead of the legacy "seenSubmittedAt" check that only guarded Verify; stale decisions fail with a coded error (`request-service.ts:921-935`, `VerificationReviewDrawer.tsx:78-82`).
- Context links from each request to the drive, round (`/tpo/drive-day/{round}`) or offer/joining page; legacy rows had no link (`tpo-global-requests-model.ts:38-46`).
- ROUND_RESCHEDULE requests appear in the global inbox; legacy decided them on the drive Rounds tab through a separate endpoint (`POST ~T/reschedule-requests/{id}/decide`, Rounds audit).
- OFFER_EXTENSION approval sets the expiry to the date the learner asked for (validated at request time) rather than a fixed +48 h (`request-service.ts:390-411`, `TpoRequestService.java:135-140`).
- A fourth status `CANCELLED` (the learner withdraws a pending request), and a per-status count nav.
- CSV exports are formula-neutralised, private reasons omitted by design (`tpo-requests-page-csv-model.ts:2-5`); keep these protections when export is widened (gap 15).
- Verification decisions are bound to private document receipts and an immutable snapshot, with a TPO verifier needing an explicit admin grant (stricter security design, `tpo-grants-service.ts:13-16`); the grant is not reachable today (gap 20), so this is a deviation to keep only if a grant UI ships, otherwise restore the legacy college-wide switch.
- Same-origin and persisted-membership checks on every mutating route (`tpo-request-decision-service.ts:13-34`, `staff-auth.ts:12-31`).
