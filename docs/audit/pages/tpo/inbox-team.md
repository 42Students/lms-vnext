## 4. Intentional differences / vNext improvements (no owner decision reference found unless stated)

- Message bodies are withheld on /tpo/messages by explicit vNext design ("Message bodies are intentionally withheld", `tpo-messages-service.ts:104-114`). No decision file was found approving this for a TPO who must read recruiters; treated as a gap (01), flagged for owner confirmation.
- Team threads are private to two named participants and re-validate both memberships inside each write (`tpo-team-internal-reply-service.ts:33-48`); legacy defaults to whole-team readable. Privacy-first default is a reasonable choice but removes the shared team memory the Team design is built on (see 15-17).
- Opening a Team thread never marks anything read; acknowledgement is an explicit POST (AGENTS rule "GET handlers never write"). Keep, but add auto-ack through a client call or an on-view action (gap 20).
- Announcements: optimistic locking with `expectedVersion` on edit/delete/undo (stale -> 409); "Recently removed" tab and "Undo removal" (restore) are additions legacy lacks (legacy delete is final); IST fixed-time inputs with explicit validation (`tpo-notice-schedule-model.ts`); audit events for create/edit/delete/restore.
- Notifications: cursor pagination with no 200-item ceiling and "View all notifications" recovery from an empty unread view; idempotent mark-read with audit event `identity.tpo_notification.acknowledged`; error states explicitly say a read failure is not an empty inbox.
- Preview of audience size is a read-only estimate that "excludes inactive memberships and disabled users", never a recipient export (`tpo-audience-preview-service.ts` header).
