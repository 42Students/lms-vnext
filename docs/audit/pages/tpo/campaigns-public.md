## 1. Legacy behaviour

### 1A. Engage > Emails tab and the compose modal
- Entry: Engage (`/tpo/recruiters`) tab strip entry `Emails` (`?view=campaigns`, IDX:35,622). Sending starts from the Actions window: select recruiter leads in the table, `Act`, group "Email them", action `Send an email` (help "One email you write, to each of them, with their name and an unsubscribe link."), button text `Write the email to {n}…`; the action marks leads with no email ("No email on file") or unsubscribed ("Asked not to be contacted") as skipped (IDX:308-310). Opens `CampaignComposer` (IDX:628-629).
- Emails tab (`Campaigns`, CMP:49-78): Card `data-testid=engage.campaigns`. Warning Alert when `emailAvailable === false`: "Campaign email is not set up yet, so nothing can be sent. Ask 42 to switch it on." (CMP:9,61). Error Alert "Couldn't load emails" (server message wins) with `Retry` (CMP:54,62). Secondary text "To send one, select recruiters in the table and choose Act, then Send an email." (CMP:63). List of campaigns, newest first, max 100, no paging (TES:43-47): title = subject; description = `{sentBy} · HH:mm D MMM YYYY` (sender = faculty first + last name; time in browser tz via `dj`); right side tags `{n} sent` (green, always), `{n} skipped` (only if >0), `{n} failed` (red, only if >0) (CMP:64-75). Empty: "No emails sent from Engage yet." (CMP:64). Loading spinner via `List loading`. Reloaded after every send (`reloadKey`). There is no per-recipient list, no body view, no export, no detail page.
- Compose modal (CMP:12-46): title `Email {n} recruiter(s)` where n = leads that have an email and are not unsubscribed; OK text `Send` (disabled when email not available or n = 0); modal resets on open. If some chosen leads are unreachable: "{k} left out: no email on file, or they asked not to be contacted." (CMP:34-36). Fields: `Subject` (required, whitespace not allowed, "Give it a subject", max 200); `Email` textarea 8 rows, max 10000 with count, required "Write the email", help "Write {name} or {company} and each person sees their own. Your signature and an unsubscribe link are added." (CMP:38-42).
- Send (`POST ~T/campaigns` {subject, body, recruiterLeadIds}, CMP:26): failure -> `message.error` (server text or "Couldn't send"); `emailAvailable === false` -> warning "Campaign email is not set up…"; success -> `"{n} sent[, {s} skipped][, {f} failed]."`; then clears the table selection, bumps the Emails list and refreshes Engage (IDX:629).
- Server rules (TES:51-115): subject/body sanitised and trimmed (200/10000), messages "Give the email a subject", "Write the email", "Choose who gets it" (no ids), "Send to at most 500 at a time" (TES:30,53-59). Inserts `tpo_email_campaign` (college, subject, body, sender faculty, recipients) and one `tpo_email_campaign_recipient` row per id with status NOT_FOUND / UNSUBSCRIBED / NO_EMAIL / NOT_CONFIGURED / SENT / FAILED, the lead email, and the SHA-256 of a 24-byte one-time unsubscribe token (V214:6-29, TES:62-110). Per reachable lead: token, merge fields subject, body (with `{name}` and `{company}` replaced), name, company, collegeName, signature (college email signature setting), `unsubscribeLink = <request Origin>/campaign-unsubscribe/<token>`; sent through mail template `recruiter-campaign` as the college (TES:84-93, TPL: header college name + "CAMPUS RECRUITMENT", "Hi {{name}},", body, signature, "Campus Recruitment Team, {{collegeName}}", footer "Prefer not to hear from us? Unsubscribe"). If the template is not configured nothing is sent and all rows are NOT_CONFIGURED/skipped (TES:37-41,81). On SENT: lead activity `EMAIL` "Campaign: {subject}" (TES:97) and, when the lead has a company, an `EMAILED` outreach row for that company if none exists (Engage > Companies communication, TES:98-103). Counts are written back to the campaign row (TES:111-113); response `{id,sent,skipped,failed,emailAvailable}`.
- Roles/scope: `/api/v1/tpo/campaigns` for the logged-in TPO's college only (TEC:32-43); recipients must belong to that college (TES:68-70).
- States: loading (list), empty, error with Retry, email-not-configured banner. No permission-denied page beyond the TPO shell.
- Responsive/keyboard: AntD list/modal; nothing special.

Tokens do not expire. Scope is that one college's recruiter lead.

## 4. Intentional differences (approved or defensible deviations)
- Opening an unsubscribe or join link never writes (GET is read-only) and unsubscribe needs an explicit same-origin POST; the form works without JavaScript (legacy needed JS). Legacy joins also need an explicit button, but counted opens on GET.
- Public links are stored hashed with an expiry and revocation (`placement_public_join_links`), legacy college links are rebuildable from a server secret. (TTL open, gap 25.)
- Campaign unsubscribe tokens are signed claims tied to college + campaign + recipient and verified against a locked recipient row (`tpo-campaign-unsubscribe-service.ts`), with a 500 UNIQUE-eligible-recipient cap and DB trigger; legacy token is a random value looked up by hash.
- Audience preview page (counts with explicit reasons: no email, opted out, bounced, Not now, outside segment) and a batch-detail page with receipt counts are new; legacy has neither. Preview excludes bounced and Not-now leads and de-duplicates by email, legacy emailed everyone with an email who had not unsubscribed. UNCONFIRMED: owner should confirm excluding Not-now/bounced is wanted.
- History is paginated (25) with an optional CSV of the page; legacy showed the latest 100 without paging.
- Provider acceptance is labelled "Provider accepted" and never as delivered, and addresses are never shown on the batch page (privacy hardening; reference `docs/decisions/*` messaging decisions, exact id UNCONFIRMED).
- Public placements page degrades gracefully per data source (branding vs statistics notices) and never shows individual data; hit target sizes are at least 44px.
