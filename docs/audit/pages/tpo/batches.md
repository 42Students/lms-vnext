## 4. Intentional differences (improvements; no decision record found, orchestrator to confirm they count as approved deviations)
1. Optimistic concurrency (`expectedVersion`) on cohort decisions, learner decisions, import commit and lifecycle changes, with 409 messages (legacy is last write wins): `decisions/route.ts:18-26`, `import-commit/route.ts:30-31`, `tpo-batch-lifecycle-model.ts:9`.
2. Undo is stricter and atomic: refuses when any touched scope has a later event or a different current value (`batch-participation-service.ts:341-436`) vs legacy "latest college action only".
3. Server-side multi-tenant fencing: persisted TPO role + `placements.manage` re-checked in each service, same-origin POST guard, non-disclosing denials (`tpo-batch-workspace-read-service.ts:14-26,44`).
4. Import is bound to this batch's active learners, never matches by name or email, rejects stale previews and caps at 200 rows (legacy matches any learner of the college).
5. Learners with more than one active section are flagged "Needs review" instead of guessed (`tpo-batch-eligibility-summary-model.ts:21-24`); summary states when it is a partial snapshot (500 cap).
6. Shareable GET filters with server pagination 12/24/48, Deadline filter and Sort selectors on the list (`page.tsx:41-48`) and name/deadline sort (extra beyond legacy).
7. Registration roster, consent evidence and per-learner registration history pages (`registrations/*`) backed by DB08 records; legacy has only a derived "Registered" step.
8. CSV exports are BOM-prefixed, `no-store`, formula-neutralised (legacy `csvCell` also neutralises formulas).
9. Mobile-first card layout and semantic forms instead of AG Grid.
