- Sidebar row "Home" (`path: "home"`, group `operate`, first row; `FE/common/lists.js:350`); the logo link goes to `/tpo/home` for any TPO workspace user (`FE/components/Sidebar/Sidebar.js` `sidebarHomeHref`). Faculty added to the placement team (not TPO accounts) get an extra sidebar row "Placement cell" -> `/tpo/home` once `GET /tpo/my-access` returns a role (`Sidebar.js:300-310`).
- Keyboard: `g` then `h` jumps to Home (`FE/components/tpo/ui/shortcuts.js:5`).
- Portal guard: `/tpo` is open to TPO (strict portal), ADMIN (college admin) and FACULTY (`FE/config/roles.js:27,36-39`). ### 1.2 Data source (one call)
`GET /api/v1/tpo/home?team=false` (`FE/api/Services/TpoHubService.js:75`, `home.js:37`). Server: `BE/controller/tpo/TpoHubController.java:42-66`, `BE/service/tpo/TpoInsightsService.java:278-410`. Returns: `needsYou` (priority-sorted cards), `followUps` (due within 24 h, max 20), `numbers` (registered, placedUnique, acceptedUnique, offers, liveDrives, unplacedReady, placedPct), `thisWeek` (calendar for 7 days minus FOLLOW_UP and BLOCKED), `batches` (batches IN_PLACEMENTS with eligible, registered, placed, invitedAt, batchId, name), `companyFunnel`, `checklist` (6 setup steps), `team` (asksOpen, asksOverdue, mentionsNew, unread, topAsk), plus compensation, funnel, byBranch and driveDay that this page does not render. `team=false` scopes drive and follow-up cards to "owned by me or unowned" (`TpoInsightsService.java:288`, follow-ups `:338`).

Card types and priority (0 = most urgent), from `TpoInsightsService.java` unless noted:

| type | when | priority | link |
|---|---|---|---|
| REGISTRATION_CLOSED | any IN_PLACEMENTS batch with eligible students never invited (`:347`) | 0 | /tpo/batches |
| DEADLINE_TODAY | published drive whose deadline is today in IST | 0 | /tpo/drives/{id} |
| REQUESTS | pending student requests; 0 if any escalated or next round within 24 h (`:330`), else 1 | 0 or 1 | /tpo/requests |
| TEAM_ASKS | open asks on me (`TpoHubController.java:52-63`); 0 if any overdue, else 1 | 0 or 1 | /tpo/team?filter=me |
| DRIVE_REQUESTS | drives in REQUEST state (`:290`) | 2 | /tpo/drives?tab=requests |
| RECRUITER_ACCESS | pending recruiter college access (`:292`) | 2 | /tpo/settings?tab=recruiters |
| SHARE_APPLICANTS, SLOTS_TO_CONFIRM, RESULTS_READY, SELECTIONS_TO_VERIFY | per drive | 1 | /tpo/drives/{id} |
| RECRUITER_MESSAGES | last message from the recruiter and older than 1 day (`:335`) | 1 | /tpo/messages |
| FOLLOW_UPS | due follow-ups (`:338`) | 1 | /tpo/recruiters?due=1 |
| NO_DEADLINE | published drive with no deadline | 1 | /tpo/drives/{id}/edit |
| CLOSING_SOON | deadline in 1 to 3 days (IST) | 1 | /tpo/drives/{id} |

The client stable-sorts the cards by `priority` again before Next up (`FE/components/tpo/home/homeRows.js:31`).

### 1.4 States
- Loading (no data yet): `DashboardSkeleton metrics=4 label="Loading placement home"`; the date and greeting render at once.
- Hard error and no data: `PanelError title={res.userMessage || "Could not load Home"} onRetry={load}`; description "Something went wrong while loading this content. Your current context has been kept."; button "Retry" with reload icon; `role=alert` (`FE/components/Common/PanelStates.jsx:80-104`).
- Background refresh: `RefreshStatus "Refreshing placement home…"` while loading with data present.
- Refresh failed with a previous snapshot: antd error Alert "Home refresh failed. Showing the last successful snapshot." with the error text and a small "Retry" button; stale rows stay (`home.js:76-85`).
- Clear state: see Next up. Missing arrays are tolerated (non-object items filtered).
- Permission denied / module off: no page-level 403 state; the sidebar shows `TpoModuleOff` ("Placements is switched off for this college", "Nothing has been deleted. When 42Students switches Placements back on, your drives, students and recruiters are all where you left them. Your college admin can contact 42Students about it.") when `/tpo/counts` answers 403 matching "not switched on | does not use placements | not available at your college" (`FE/components/tpo/TpoModuleOff.jsx:1-20`, `Sidebar.js:339-343`). Other 403s fall into the page's own error state with the server message.
- Reload: `visibilitychange` to visible re-runs the load (no refresh button); one request at a time (`loadInFlightRef`) (`home.js:28-55`).

## 4. Intentional differences (improvements or approved deviations)
- Access is decided by the central `placements.manage` permission instead of role strings. A college admin without a TPO account gets a placement-cell landing with links to the college placements pages (`tpo-workspace-access-model.ts:77-89`; docs/audit/acceptance/2026-10-16-pass6.md:408). The legacy page itself works for admins, so this is a narrower page for them (see TPO-home-27).
- Next up for a drive links straight to the drive (`/tpo/placements/jobs/{jobId}`); the requests count is one aggregate SQL count and never loads request text (`tpo-pending-requests-count-service.ts`).
- Bell links are validated (same-origin `/...` only, `tpo-bell-panel.tsx:31`); legacy pushes `n.link` unchecked (`TpoBellPanel.jsx:66-69`). Mark-all is a same-origin-checked POST that refreshes server data.
- The page is server-rendered (no client waterfall or skeleton flash). Keep this when closing 03 to 14, by one college-scoped read model rather than a client fetch.
- Already equal to legacy: sidebar labels, groups and order (`shell-model.ts:187-202`), the `/tpo` redirect, and the Ctrl/Cmd+K shortcut with the same trigger label.
