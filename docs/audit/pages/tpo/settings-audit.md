## 4. Intentional differences (improvements in vNext, keep)
- Optimistic concurrency (`expectedVersion`) and same-origin POST on every settings write; stale edits get a message instead of overwriting (rules, job types, blocked dates, prep, grants).
- Settings writes emit immutable `activity_events` with before/after (rules, job types, blocked dates, prep, grant/revoke, trust); legacy logged no event for placement-rules and what-companies-see saves.
- Recruiter grants always expire: grants carry `valid_until`, and an ACTIVE row with no expiry fails closed (T-S1-01).
- Recruiter access list is paginated server-side (25/page) with name/company search and an export that omits contact data; legacy exports phone-masked rows client-side.
- Company-relationship trust with a mandatory reason (8-500 chars) and per-college scope; read-only explicit domain list.
- Audit: server-side pagination (25/50/100) instead of a 500/5000 client cap, IST date inputs, formula-neutralised CSV, and unions of application/screening/round/result/offer/joining/share histories that legacy's single table lacked. Read-only My notifications inbox and Placement team directory inside Settings; Job-specific eligibility list on Rules; static Communication templates.
