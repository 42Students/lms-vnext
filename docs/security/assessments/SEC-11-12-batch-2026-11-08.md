# SEC-11 files and SEC-12 browser: batch assessment (2026-11-08)

Method: code search and read of the files named in each row; nothing run beyond the existing unit tests. Nothing here is VERIFIED. Each row is in `scripts/security/area-mappings.json`, which feeds `tracker-updates-pending.json`.

- **SEC-12-003, SEC-12-004, SEC-12-005, SEC-12-007** (implemented, unverified): Rich text goes through a strict rebuild (sanitizeCourseDisplayHtml in src/modules/courses/course-display-validation.ts): all text is escaped, only a short tag allowlist is reconstructed and every attribute is dropped. Only 8 files use dangerouslySetInnerHTML: 3 course components fed by that sanitizer and 5 static marketing/policy pages. Unit tests: course-display-content.test.ts and chat7-superadmin-course-authoring-break.test.ts.
- **SEC-12-006** (partial): No client code builds HTML from location, hash or query; the CSP (nonce scripts, connect-src 'self') blocks injected script, but no DOM-XSS scanner or Trusted Types is in place.
- **SEC-12-012, SEC-12-013** (implemented, unverified): No Access-Control-Allow-* header is set anywhere in src, so browsers enforce same-origin; credentialed cross-origin access and wildcard CORS do not exist.
- **SEC-12-014** (implemented, unverified): Search of src for secrets in query strings (token, otp, password, secret, code) finds none; share and invite tokens travel in the path and are stored hashed, sign-in codes only in POST bodies.
- **SEC-12-015, SEC-12-016** (implemented, unverified): Browser storage holds interface preferences only (table columns and sort, recent searches, last selected college or membership key, a sign-out broadcast key); no token, code or personal data. Sign-out writes lms:signout so other tabs leave, the session cookie is HttpOnly and server-revoked.
- **SEC-12-018** (partial): No third-party script tags or analytics widgets in src; the only third-party content is the YouTube iframe API for lesson video. No subresource integrity or formal inventory of embeds.
- **SEC-12-019** (implemented, unverified): Authorization is enforced in route() and the services; the role-by-route matrix and unauthenticated gate test the server regardless of what the UI hides.
- **SEC-11-009, SEC-11-012, SEC-11-017** (implemented, unverified): Upload types are an allowlist (src/modules/storage/file-policy.ts: documents, three image types, zip for some flows; no HTML, SVG or executables). Signed links force attachment unless the type is a PDF or png/jpeg/gif/webp, filenames are ASCII-cleaned and percent-encoded in Content-Disposition, and responses carry private, no-store.
- **SEC-11-011, SEC-11-013, SEC-11-015, SEC-11-016** (partial): Zip is accepted for some flows but the server never extracts uploads, there are no conversion or preview workers, and object keys are opaque and scope-prefixed rather than user paths. Nothing is proved by a hostile-archive or traversal test.
- **SEC-11-014, SEC-11-019** (implemented, unverified): File access is decided from database rows (owner, college, resource) at every signed-URL request, with a 5-minute ceiling, so ended memberships stop working on the next request; same-college learner probe found no foreign data.
- **SEC-11-004, SEC-11-020** (partial): Signed links are short-lived; the legacy bucket is public (see SEC-11-001). Bulk exports are audited as api.export events; individual file downloads are not yet audited.
- **SEC-11-018** (gap): No retention or deletion policy is defined for submitted documents (owner and legal decision; SEC-22).
