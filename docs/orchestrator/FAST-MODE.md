# FAST MODE (owner directive, in force until the owner says otherwise)

The owner wants every audit gap closed as fast as possible. Correctness is checked and fixed in a separate pass at the END, under a strategy the owner will announce. Until then:

1. **(v2, replaces the old 'push to main' rule) Push to YOUR OWN BRANCH `chatgpt/chat-N-b`** (N = your lane number; create it from the latest `main` if it does not exist). Never push to `main`; never open a pull request. The orchestrator merges your branch into main in fast batches. Ignore any later line in this file that says 'push directly to main': read it as 'push to your branch'. Workflow for every change: `git fetch origin`, merge `origin/main` into your branch (do it at the start of every WP and whenever a push is rejected), edit, commit, `git push origin HEAD:chatgpt/chat-N-b`. If the push is rejected because main moved, fetch, rebase and push again. Push after EVERY gap or small group of gaps (cite every gap ID in the commit message). Never batch a whole round into one push.
2. **No tests, no typecheck, no lint, no build, no CI waiting.** Do not run or wait for anything. Do not write new tests unless the gap itself is about tests. Do not stop to fix lint or type warnings you did not introduce. Never revert other lanes' work.
3. **Never block.** If a gap is unclear, take the audit's recommended default and move on. Skip only: security-sensitive owner decisions (marked SKIP in the work package) and anything that needs real file storage keys, secrets, or production access.
4. **Stay in your lane's directories** (see docs/audit/work-packages/README.md ownership table; src/components/shell is chat-9 only) so pushes to main do not collide. If a file you need is owned by another lane, make the minimal edit anyway and keep going.
5. **New tables/columns:** write the schema and a proposal under `docs/proposed-migrations/<id>.sql` and keep going; the orchestrator registers migrations.
6. **Update status:** mark finished WPs in your queue file (`docs/orchestrator/queues/chat-N.md`) in the same pushes. Keep going down the queue without waiting for the orchestrator: when a WP is done, take the next TODO WP immediately.
7. Final summary of each reply: gap IDs finished / remaining. Do not report test results.
8. **Start EVERY commit message with your lane tag in square brackets**, e.g. `[chat-2] fix(tpo): TPO-recruiters-12 ...`. The orchestrator tells lanes apart by this tag.
