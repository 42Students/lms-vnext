# UX coverage closure (owner wants 99.99 percent sure, everything covered, exhaustively)

Source of truth: `docs/audit/ux/COVERAGE-MATRIX.md`, generated by `node scripts/audit/ux-coverage.mjs`. The orchestrator regenerates it after every merge. The goal is every gap count at zero, or a written waiver in `docs/audit/ux/COVERAGE-WAIVERS.md` (route/file, reason, who approved) for the few that are genuinely not applicable.

## What each gap type means and how to close it
- **Routes without a UX test mention**: add `tests/unit/UX-<area>-<page>-NN.test.ts` that names the route and its page file path and asserts real behaviour (states, 44px targets, labelled controls, empty copy, no raw errors). A test that only checks the file exists does not count.
- **Overlay components with no UX test/note** (dialogs, drawers, sheets, confirm flows): add a test per component asserting title via aria-labelledby, focus trap and return, Escape and backdrop behaviour, unsaved-change protection, destructive confirmation with stated consequence, 44px controls. Name the component file in the test and in a note in `docs/audit/ux/`.
- **Routes using no shared components**: open the page, move hand-rolled headers, cards, buttons and inputs to the shared kit (`PageHeader`, `Card`, `Button`, `Input`, `DataTable`, `Dialog`, `EmptyState`, `ErrorState`). Legacy wording unchanged.
- **Raw `<table>` outside DataTable**: replace with `DataTable` (explicit `empty` copy, mobile priorities) or document why not in the waiver file.
- **target=_blank without noopener**: remove the popup (same-tab) or add `rel="noopener noreferrer"`, per the playbook.
- **Shared UI components with no test**: add direct tests for the 4 listed primitives.
- Afterwards re-run the audit for your area yourself: read each page against the 21 rubric checks and fix what you find.
